# SPS 衣櫃保存與容量

[文件索引](../README.md) · [互動架構圖](https://awdrrawd.github.io/BC-AEE/docs/architecture/index.html)

## 容量規則

SPS 衣櫃預設 100 格，依非空服裝數量，在 90、190、290、390、490、590、690、790、890 件時擴充，容量依序為 200、300、400、500、600、700、800、900、984 格。最多 984 格，可整除每頁 6 或 8 人物的顯示方式。收藏或標籤不計為服裝；刪除服裝不縮減已保存的容量。

舊資料若分散在較後面的槽位，容量會保留到能涵蓋最高有效位置，避免藏起服裝。若第 984 格以後仍有服裝或名稱，停止載入／遷移並提示先使用舊版匯出整理；不截斷、不刪除來源。這項容量規則只適用 SPS，BC/WCE/LCE 線上衣櫃與本地衣櫃維持既有容量。

衣櫃翻頁支援首尾循環：第一頁按上一頁到最後一頁，最後一頁按下一頁回第一頁；滾輪、上下滑動及拖曳換頁也使用同一規則。只有一頁時上一頁／下一頁停用，首頁／末頁快捷鍵仍直接前往指定頁。

## 單槽記錄與發布索引

`core/spsWardrobe.ts` 專責資料格式、載入、容量與提交；`wardrobeStorage.ts` 負責帳號及畫面狀態；`wardrobeMutation.ts` 在修改記憶體之前鎖定使用者操作。

- 服裝、名稱、收藏、標籤一起存入 `liko-aee:wardrobe/v2/slot/<index>/<revision>`，index 從 0 起算。
- 固定的 `liko-aee:wardrobe/v2/index` 保存版本、容量及各槽目前使用的記錄 key。
- 修改單槽只上傳該槽新記錄及索引；交換或批次匯入先寫完所有新記錄，再發布一次索引。刪除移除索引引用，不刪除舊記錄。
- 任一記錄寫入失敗不發布新索引；讀取者仍看到原版本。索引提交的回應遺失時，會再讀索引確認結果。
- 保存期間停用衣櫃操作；失敗不關閉編輯／匯入對話框。SPS 遇到不確定結果或衝突時停用修改，必須重新載入確認伺服器版本，再重試。
- 本地 IndexedDB 的衣櫃寫入也改為等待成功。BC 線上來源仍只能確認資料已交給遊戲更新佇列，不能聲稱伺服器已完成持久化。

## 舊資料與相容性

沒有 v2 索引時，只讀舊的 `liko-aee:wardon/<chunk>`，严格檢查版本、服裝與名稱。第一次成功保存會把有效舊服裝複製成單槽記錄並發布索引；舊 chunk 保留，失敗後可重新載入並再試。

舊版的 SPS 收藏／標籤與 local 共用同一設定 key，無法可靠判定歸屬，因此不自動複製本地標籤到 SPS；原本 local metadata 保留。v2 的 metadata 與服裝一起存入雲端。

v2 發布後不再混讀舊 chunk。舊版 AEE 不認得此索引，在舊版進行的寫入不會自動合併到新版；跨裝置應使用同一新版並先匯出備份。

## 實作限制與驗收

提交前會比較遠端索引與載入版本，阻止覆蓋已知的新變更；提交後再確認結果。但目前未使用伺服器條件寫入，兩台裝置完全同時提交仍可能最後寫入者勝出，不具備跨裝置交易保證。

旧記錄、失敗上傳產生的未引用記錄和舊 chunk 不自動刪除，雲端用量會累積。配額不足會停止保存；自動清理需要另外設計保留期、引用追蹤與備份流程。已依官方 cursor 分頁契約讀取完整清單，並補上異常游標測試。

新增回歸腳本驗證容量邊界、單槽及批次發布、故障不發布、回應遺失、帳號檢查、舊資料保留、重複操作及 metadata 回復。真實 OAuth/SPS 與遊戲內互動仍需實機驗收，測試不會寫入玩家雲端衣櫃。

## 2026-09-13：封存與分頁核對

依 [SPS 官方介面](https://github.com/bondage-studio/studio-player-storage/blob/main/README.md)及[伺服器實作](https://github.com/bondage-studio/studio-player-storage/blob/main/src/index.ts)核對，key 清單以 cursor 分頁，每頁最多 1000 筆。客戶端持續讀到 cursor 為 null，並拒絕重複游標、格式錯誤及跨帳號結果。私人與公開資料共用每位玩家 5000 個 key／128 MiB 配額；單一值上限 10 MiB。

衣櫃設定的儲存頁新增「匯出 SPS 封存與報告」，僅在選取且載入 SPS 衣櫃時啟用。它讀取 AEE 衣櫃舊分塊、v2 索引與槽位紀錄，輸出原始 JSON 值及未被此次索引引用的紀錄清單。過程檢查帳號、索引是否改變及引用紀錄是否齊全；原始值累計超過 32 MiB 時停止。此封存可交給衣櫃匯入功能，先預覽服裝並選擇目標位置後才保存；封存不含公開圖片內容。

封存只反映此次讀取結果，不是跨裝置一致性快照；服務端列舉與寫入沒有交易保障。未被引用可能代表其他裝置尚未發布的寫入，因此不執行 DELETE。舊圖片、舊紀錄的自動清理，以及跨裝置絕不覆蓋的保存，仍需上游提供條件更新／交易或其他可證明安全的協定；客戶端讀前、讀後比較不能取代此保障。

測試以模擬介面驗證分頁、索引變動、缺少紀錄與帳號變更，沒有操作玩家雲端資料；真實 BC 遊戲與 SPS 帳號仍需驗收。

### 從封存還原

在衣櫃的檔案匯入入口選擇 aee-sps-archive JSON，使用既有匯入預覽與位置選擇流程。只還原封存索引引用的服裝、名稱、收藏與標籤，不會重播未引用的歷史槽位或直接覆寫雲端索引。沒有 v2 索引的舊封存依原分塊位置讀取。空服裝不列入匯入項目，容量依目標衣櫃的既有規則處理。

解析封存完全離線，不認證、不上傳；缺少引用紀錄、未知版本、異常格式及超過 32 MiB 的原始值會拒絕整份封存。圖片仍使用原有 SPS 連結，因此此備份不能保證公開圖片刪除後仍能顯示。

## 最後驗收與保留限制（2026-09-13）

載入完成前會再次核對索引；期間若觀察到其他裝置發布，保持不可編輯並要求重新載入。SPS 衣櫃鏡像同時綁定 Player 實體與會員編號，同一會員重新建立人物實體也不能沿用舊請求結果。

以下仍需在真實遊戲以備份過的測試衣櫃驗收，模擬測試與架構圖瀏覽器測試不能代替：

| 操作 | 預期結果 |
| --- | --- |
| 存到第 90／190 件、再刪除 | 容量增至 200／300；刪除不縮容，最多 984 格。 |
| 第一頁按上一頁，最後頁按下一頁 | 分別回到最後頁、第一頁。 |
| 匯出封存後匯入到本地空位 | 可預覽、選位置，名稱／收藏／標籤保留，不覆寫其他槽位。 |
| 舊圖遷移後重新穿戴、改畫新圖再穿回舊服裝 | 新版 AEE 能顯示遷移圖片，舊服裝引用不被新圖覆蓋。 |
| 保存途中斷線或切換帳號 | 不假報成功；不寫入另一帳號，保留備份並重新載入確認。 |
| 兩台裝置依序修改同一衣櫃 | 舊快照保存被拒絕，重新載入後才能重試。 |

「兩台裝置同時通過索引比較」仍可能競爭，並未承諾此情境不覆蓋。完整保障需要 SPS 服務端的條件提交與可驗證的一致性語意；客戶端加一次鎖定 key 不足以解決。自動刪除還需可靠的引用判定、在途寫入保護與復原機制，故維持不刪除策略。公開圖片可能被其他衣櫃或玩家引用，不能只依當前衣櫃的未引用清單刪除。

完整操作步驟與結果回報方式見 [DEV 驗收指南](./dev-acceptance.md)。
