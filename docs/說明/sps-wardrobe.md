# SPS 衣櫃保存與容量

[文件索引](../README.md) · [互動架構圖](https://awdrrawd.github.io/BC-AEE/docs/architecture/index.html)

## 容量規則

SPS 衣櫃預設 100 格，依非空服裝數量，在 90、190、290、390、490、590、690、790、890 件時擴充，容量依序為 200、300、400、500、600、700、800、900、984 格。最多 984 格，可整除每頁 6 或 8 人物的顯示方式。收藏或標籤不計為服裝；刪除服裝不縮減已保存的容量。

舊資料若分散在較後面的槽位，容量會保留到能涵蓋最高有效位置，避免藏起服裝。若第 984 格以後仍有服裝或名稱，停止載入／遷移並提示先使用舊版匯出整理；不截斷、不刪除來源。這項容量規則只適用 SPS，BC/WCE/LCE 線上衣櫃與本地衣櫃維持既有容量。

衣櫃翻頁支援首尾循環：第一頁按上一頁到最後一頁，最後一頁按下一頁回第一頁；滾輪、上下滑動及拖曳換頁也使用同一規則。只有一頁時上一頁／下一頁停用，首頁／末頁快捷鍵仍直接前往指定頁。

## 單槽記錄與發布索引

`core/spsWardrobe.ts` 專責資料格式、載入、容量與提交；`wardrobeStorage.ts` 負責帳號及畫面狀態；`wardrobeMutation.ts` 在修改記憶體之前鎖定使用者操作。

- 服裝、名稱、收藏、標籤一起存入 `liko-aee:wardrobe/v2/slot/<index>/<revision>`，index 從 0 起算。
- 固定的 `liko-aee:wardrobe/v2/index` 保存版本、容量及各槽目前使用的記錄 key。
- 修改單槽只上傳該槽新記錄及索引；交換或批次匯入先寫完所有新記錄，再發布一次索引。刪除移除索引引用，不刪除舊記錄。
- 任一記錄寫入失敗不發布新索引；讀取者仍看到原版本。索引提交的回應遺失時，會再讀索引確認結果。
- 保存期間停用衣櫃操作；失敗不關閉編輯／匯入對話框。SPS 遇到不確定結果或衝突時停用修改，必須重新載入確認伺服器版本，再重試。
- 本地 IndexedDB 的衣櫃寫入也改為等待成功。BC 線上來源仍只能確認資料已交給遊戲更新佇列，不能聲稱伺服器已完成持久化。

## 舊資料與相容性

沒有 v2 索引時，只讀舊的 `liko-aee:wardon/<chunk>`，严格檢查版本、服裝與名稱。第一次成功保存會把有效舊服裝複製成單槽記錄並發布索引；舊 chunk 保留，失敗後可重新載入並再試。

舊版的 SPS 收藏／標籤與 local 共用同一設定 key，無法可靠判定歸屬，因此不自動複製本地標籤到 SPS；原本 local metadata 保留。v2 的 metadata 與服裝一起存入雲端。

v2 發布後不再混讀舊 chunk。舊版 AEE 不認得此索引，在舊版進行的寫入不會自動合併到新版；跨裝置應使用同一新版並先匯出備份。

## 實作限制與驗收

提交前會比較遠端索引與載入版本，阻止覆蓋已知的新變更；提交後再確認結果。但目前未使用伺服器條件寫入，兩台裝置完全同時提交仍可能最後寫入者勝出，不具備跨裝置交易保證。

旧記錄、失敗上傳產生的未引用記錄和舊 chunk 不自動刪除，雲端用量會累積。配額不足會停止保存；自動清理需要另外設計保留期、引用追蹤與備份流程。本版未新增服務分頁契約，舊格式遷移仍依 SPS 既有 list 回應，服務端分頁能力尚待確認。

新增回歸腳本驗證容量邊界、單槽及批次發布、故障不發布、回應遺失、帳號檢查、舊資料保留、重複操作及 metadata 回復。真實 OAuth/SPS 與遊戲內互動仍需實機驗收，測試不會寫入玩家雲端衣櫃。
