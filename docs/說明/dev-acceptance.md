## 1. 載入正確版本

測試已合併功能時使用 main；若要驗證本次整理，將下面的 main 換成 codex/wardrobe-cleanup。先確認工作目錄沒有未提交修改，再切換分支：

```powershell
git fetch origin
git switch main
git pull --ff-only
git rev-parse HEAD
npm ci
npm run build
npm run preview -- --host 127.0.0.1 --port 5174 --strictPort
```

請使用自己的 Chrome／Edge 遊戲分頁，按 Ctrl+Shift+J 開啟 Console。Codex 內建瀏覽器此次無法開啟 Console，因此不使用它載入本地測試版。

保持終端開啟。在測試遊戲分頁停用原本會自動載入 AEE 的插件管理器項目／UserScript，重新整理並登入測試帳號。只停用 AEE，不需停用其他安全機制。然後在該遊戲分頁的開發者工具 Console 輸入：

```javascript
import('http://127.0.0.1:5174/assets/main.js?v=' + Date.now());
```

Network 應顯示從 127.0.0.1:5174 載入 main.js 與 app.js。若出現 Already loaded，先移除重複的 AEE 載入來源再重新整理；不要手動刪除 window.Liko.AEE 來重複初始化。若瀏覽器封鎖 localhost 請求，記錄錯誤，不要停用瀏覽器安全機制。也可等 PR 合併、main 的 Deploy Pages 成功後，改用原本的正式 Loader 測試該提交。

只 push 功能分支不會更新正式 GitHub Pages。衣櫃存檔位於遊戲來源／帳號範圍，本地來源也請先匯出備份。

## 3. 最小功能驗收（約 15–30 分鐘）

只使用已確認可新增測試服裝的帳號。先匯出原有服裝；雲端封存不包含公開圖片本體，不是完整圖片備份。

| 測試 | 操作 | 通過條件 |
| --- | --- | --- |
| 保存與 metadata | 在空槽保存服裝 A，命名 DEV-A，加收藏與標籤 DEV；重新載入 SPS | 名稱、服裝、收藏、標籤均保留。 |
| 來源隔離 | 切到本地與遊戲線上同編號槽，再切回 SPS | 不串用 SPS 的收藏與標籤。 |
| 單次保存 | 保存期間再次點保存／交換／匯入 | 不重複提交；等待結束後才恢復操作。 |
| 翻頁 | 清除搜尋與收藏篩選，第一頁按上一頁、最後頁按下一頁；分別試 6 與 8 格模式 | 第一頁與最後頁可互相跳轉。 |
| 封存還原 | 在儲存設定匯出 SPS 封存，使用檔案匯入，選本地空位 | 有預覽與目標位置；確認前不改資料，完成後 A 與 metadata 一致。注意預設 sourceIndex 可能指向已有槽位，要檢查取代標記。 |
| 新圖片歷史 | 畫 A 並保存到服裝 A；再畫 B 存成服裝 B；輪流穿回 | A 仍是 A、B 仍是 B；重開遊戲後也成立。 |
| 舊圖批次遷移 | 用已備份、確含 CustomDraw 的測試服裝，點儲存設定「備份並遷移舊繪圖」 | 先下載標準衣櫃備份，再上傳、最後保存；穿回圖片一致。若沒有舊圖，應提示無可遷移資料，不能算遷移通過。 |
| 編輯取消 | 開始繪圖、改遮罩／優先度，取消；再重新開啟 | 回復進入前內容；確認保存則保留改動。 |

## 4. 容量邊界，不必手動存 90 次

100→984 的擴充是 SPS 來源行為，不是所有來源都有 984 格。先從測試帳號匯出至少一套可正常穿戴的標準衣櫃 JSON（例如 sample.json），再在倉庫終端執行：

```powershell
node scripts/create-wardrobe-test-file.mjs sample.json test-89.json 89
node scripts/create-wardrobe-test-file.mjs sample.json test-90-188.json 99 90
```

產生器只在本機複製第一套有效服裝、設定測試名稱／收藏／標籤，不連網；不覆寫既有輸出檔。請選不含私人繪圖的簡單測試服裝。

1. 在空白 SPS 衣櫃匯入 test-89.json，確認 89 個新增、0 個取代；容量維持 100。
2. 手動保存一套到下一個空槽，總數達 90，容量應變 200。
3. 匯入 test-90-188.json，這批使用從 0 計數的 90–188 槽，總數達 189，容量仍為 200。
4. 再保存一套，總數達 190，容量應變 300。
5. 更高邊界同理，289→290、389→390…889→890，最後容量由 900 變 984。可產生後續 99 件批次，START_INDEX 為 190、290…790。
6. 容量 984 後，可用 `COUNT=94 START_INDEX=890` 產生剩餘測試槽。填滿後不能新增第 985 格；備份後移除一套，容量不縮小。

不要一次把 984 件檔案匯入剛開啟的 100 格衣櫃：匯入預覽依目前容量規劃，超出容量的項目會略過。雲端大量測試會消耗 key 與配額；最高邊界已有單元測試，日常驗收跑到 190 即可，984 全量僅在專用帳號有需要時執行。

## 5. 故障與雙裝置驗收

- **網路失敗**：在 DevTools Network 切換 Offline，再保存測試服裝。應顯示失敗，不能提示成功；恢復 Online、重新載入後確認實際資料。這只能驗證送出前斷線；送出後回應遺失由模擬測試涵蓋，勿混為一談。
- **慢速／切帳號**：使用網路節流載入 SPS 或上傳測試圖，未完成時離開測試帳號，再登入另一個測試帳號。舊結果不能套入新帳號；恢復正常網路後可以重新載入。
- **舊快照**：兩個可同時登入的獨立瀏覽器載入同一測試衣櫃。A 保存並等另一端可讀到新結果，再讓仍持有舊快照的 B 保存；B 應拒絕保存並要求重新載入。如果遊戲不允許同帳號雙登入，標記未測，不要以兩個不同帳號代替。
- **完全同時保存**：本版不保證此情境不覆蓋。服務端缺少條件提交，兩端可能同時通過讀前比較；不把這項標記為通過。請先避免同時編輯同一雲端衣櫃。
- **自動清理**：本版沒有 DELETE 清理操作，這是保留策略。未引用紀錄不等於可刪除，公開圖片可能仍被其他服裝引用。

## 6. 結果回報與退回正式版

每項記錄：通過／失敗／未測、提交 SHA、來源（本地／線上／SPS）、操作順序、預期與實際結果。失敗時附錯誤訊息；不要貼 OAuth token、Authorization 標頭或完整私人服裝 JSON。

測試結束後關閉本地 preview、恢復原 AEE Loader 並重新整理。這只切換程式，不會自動回滾雲端資料。需要恢復服裝時先使用新版 AEE 的匯入預覽與備份，確认正確後再切換；舊版未必讀得懂 v4 圖片引用。不要直接刪除雲端歷史紀錄。
